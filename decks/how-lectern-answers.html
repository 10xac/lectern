How lectern answers a question

Every slide in a deck gets its own agent.

A ten-minute tour of the code.

Welcome everyone. This talk walks through what happens between typing a question and seeing an answer with citation chips.

A deck becomes slide agents

  • Upload an HTML deck, a .pptx file or a Google Slides export.
  • The ingest graph detects the format, parses it, normalises it and builds an outline.
  • Each slide keeps its title, its body text and its presenter notes.
The three adapters all produce the same Deck model, so nothing after ingest cares where a deck came from.

The answer graph

gate, route, assemble, answer, cite, persist.

Persist always runs last and writes the trace.

Point at the trace drawer: every step shows the block ids it used and how long it took.

Citations are checked

The cite node keeps only markers that name a block in the assembled context.

After two failed revisions the agent says it cannot support an answer.

Handoffs between slides

Ask slide 2 about slide 5 and slide 5's agent answers.

A question is handed off at most once, so agents never ping-pong.

Questions about the whole deck go to the deck agent.
